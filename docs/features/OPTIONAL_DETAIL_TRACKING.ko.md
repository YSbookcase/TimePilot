# 선택형 상세 추적 모드

## 1. 목적

TimePilot의 기본 기록 단위는 앱 사용 시간이다.

선택형 상세 추적 모드는 사용자가 명시적으로 선택한 경우에만 앱보다 더 자세한 정보를 기록할 수 있는지 검토하기 위한 기능 방향이다.

이 기능은 가치가 크지만 개인정보 민감도도 높다. 따라서 기본값은 반드시 꺼짐이어야 하며, 사용자가 수집 범위와 위험을 이해한 뒤 켤 수 있어야 한다.

---

## 2. 기본 원칙

- 기본 모드는 앱 단위 기록만 수행한다.
- 창 제목, 문서명, 브라우저 도메인, URL은 기본 저장하지 않는다.
- 상세 추적은 단계별 선택 옵션으로 제공한다.
- 상세 추적은 앱별 개별 허용을 우선하되, 사용자가 명시적으로 선택하면 전역 적용도 제공할 수 있다.
- 전역 적용을 켤 때는 민감 정보 저장 가능성을 알리는 확인 팝업을 표시한다.
- 앱별 상세 추적도 기본값은 꺼짐이다.
- 상세 추적 데이터는 로컬에 저장한다.
- 상세 추적을 켤 때 개인정보 안내를 표시한다.
- 상세 추적 데이터는 삭제, 내보내기, 백업/복원 정책에서 별도로 다룬다.

---

## 3. 추적 단계

### 3.1 Level 0: 앱 단위 기록

기본 모드다.

기록 대상:

- 앱 이름
- 프로세스 이름
- 실행 경로
- 사용 시간
- 유휴 시간
- 실행 구간

저장하지 않는 정보:

- 창 제목
- 문서명
- 웹페이지 제목
- 브라우저 도메인
- 전체 URL

### 3.2 Level 1: 창 제목 기록

사용자가 선택한 경우 활성 창 제목을 기록하는 단계다.

예:

```text
Visual Studio - TimePilotStorage.cs
Google Chrome - GitHub Issues
Microsoft Word - Report.docx
```

장점:

- 브라우저 확장 없이 구현 가능성이 높다.
- 앱 내부에서 어떤 작업을 했는지 대략 파악할 수 있다.

위험:

- 문서명, 채팅방 이름, 이메일 제목, 웹페이지 제목이 포함될 수 있다.
- 사용자가 의도하지 않은 개인정보가 저장될 수 있다.

정책:

- 기본 꺼짐
- 명확한 안내 필요
- 저장 기간 또는 삭제 기능 필요

### 3.3 Level 2: 브라우저 도메인 기록

브라우저 사용 중 방문 도메인 수준만 기록하는 단계다.

예:

```text
github.com
learn.microsoft.com
youtube.com
```

장점:

- 전체 URL보다 개인정보 노출이 적다.
- 웹 사용 시간을 분류하거나 분석하는 데 유용하다.

위험:

- 도메인만으로도 관심사, 업무, 건강, 금융, 개인 활동이 드러날 수 있다.
- 브라우저별 구현 방식이 다르다.

정책:

- 기본 꺼짐
- 창 제목 기록보다 더 강한 개인정보 안내 필요
- 브라우저별 제약 조사 필요

### 3.4 Level 3: 전체 URL 기록

전체 URL을 기록하는 단계다.

예:

```text
https://example.com/path?query=value
```

위험:

- 검색어, 문서 ID, 토큰, 개인 식별 정보가 포함될 수 있다.
- 기록/내보내기/백업 파일의 개인정보 위험이 크게 증가한다.

정책:

- 일반 기능으로는 신중하게 보류한다.
- 고급 옵션 또는 Pro 후보로 검토한다.
- 구현 전 데이터 삭제, 마스킹, 보관 기간 정책이 필요하다.

---

## 4. 구현 방식 후보

### 4.1 창 제목 기반

활성 창의 제목을 읽어 기록한다.

장점:

- 앱 내부 구현만으로 시작 가능하다.
- 브라우저, 문서 편집기, IDE 등 다양한 앱에 적용 가능하다.

단점:

- 제목 형식이 앱마다 다르다.
- URL이나 도메인을 안정적으로 얻기 어렵다.
- 개인정보가 섞일 수 있다.

우선순위:

- 1차 검토 후보

### 4.2 브라우저 방문 기록 DB 읽기

Chrome, Edge, Firefox 등의 로컬 방문 기록 DB를 읽는 방식이다.

장점:

- 도메인/URL 정보를 비교적 명확하게 얻을 수 있다.

단점:

- 브라우저 실행 중 DB 잠금 문제가 생길 수 있다.
- 브라우저별 저장 구조가 다르다.
- 사용자가 기대하는 실시간 추적과 다를 수 있다.
- 개인정보 위험이 매우 크다.

우선순위:

- 리서치 후보

### 4.3 브라우저 확장 프로그램

브라우저 확장 프로그램을 통해 현재 탭 도메인 또는 URL을 TimePilot에 전달하는 방식이다.

장점:

- 현재 탭 정보를 더 정확하게 얻을 수 있다.
- 사용자가 브라우저 권한을 명확히 승인할 수 있다.

단점:

- 브라우저별 확장 배포가 필요하다.
- 앱과 확장 프로그램 간 통신 구조가 필요하다.
- 개발/배포/보안 부담이 크다.

우선순위:

- 장기 검토 후보

## 5. UI 방향

환경 설정에는 상세 추적을 별도 섹션으로 둔다.

예:

```text
상세 추적
[ ] 상세 추적 기능 사용

앱별 상세 추적
앱 이름              창 제목    도메인    URL
Google Chrome       [ ]        [ ]       [ ]
Visual Studio       [ ]        -         -
Microsoft Word      [ ]        -         -
```

상세 추적은 앱별 개별 관리를 우선으로 보여주되, 사용자가 필요하면 전역 적용도 선택할 수 있게 한다.

- 앱별 설정은 기본 관리 방식이다.
- 전역 적용을 켜면 해당 상세 추적 수준이 대상 앱 전체에 적용될 수 있으므로 강한 확인 팝업을 표시한다.
- 전역 적용은 사용자가 명시적으로 선택해야 하며 기본값은 꺼짐이다.
- 앱별 설정에는 기본 안내 문구를 표시하고, 개별 앱에서 어떤 정보가 기록되는지 알 수 있게 한다.
- 브라우저 도메인 또는 URL 기록은 브라우저 앱에만 표시하거나 활성화한다.
- 앱별 설정은 앱 분류 관리 또는 별도 상세 추적 관리 화면에서 연결할 수 있다.

전역 상세 추적을 켤 때는 확인 팝업을 표시한다. 앱별 상세 추적을 허용할 때는 기본 안내 문구를 표시하고, 필요하면 추가 확인을 둘 수 있다.

안내 예시:

```text
상세 추적은 창 제목, 웹사이트, 문서명 등 민감한 정보를 저장할 수 있습니다.
이 데이터는 로컬에 저장되지만, 백업/내보내기 파일에 포함될 수 있습니다.
필요한 경우에만 사용하세요.
```

## 6. 저장 정책

상세 추적 데이터는 기존 앱 사용 기록과 분리해서 저장하는 것이 좋다.

후보 테이블:

```text
detail_activity_sessions
- id
- foreground_session_id
- app_id
- detail_type
- title
- domain
- url
- started_at
- ended_at
- duration_ms
```

다만 전체 URL 저장은 별도 정책이 확정되기 전까지 보류한다.

---

## 7. 삭제와 내보내기 정책

상세 추적 데이터는 일반 사용 기록보다 민감하다.

필요한 기능:

- 상세 추적 데이터만 삭제
- 특정 기간 상세 추적 데이터 삭제
- 백업/내보내기 시 상세 추적 포함 여부 선택
- 원시 데이터 내보내기 안내 문구 보강

---

## 8. 현재 결정

- 기본값은 앱 단위 기록이다.
- 상세 추적은 기본 꺼짐이다.
- 상세 추적은 앱별 개별 허용 방식을 우선하되, 전역 적용은 강한 확인 후 사용할 수 있다.
- 1차 구현 후보는 창 제목 기록이다.
- 브라우저 도메인 기록은 추가 리서치 후 결정한다.
- 전체 URL 기록은 보류한다.
- 상세 추적 데이터는 별도 테이블로 분리하는 방향을 우선 검토한다.
- 선택형 상세 추적은 Pro 후보 기능으로 둔다.
- 공개 Community 저장소에는 정책, UX 기준, 저장 계약, 확장 지점까지만 둔다.
- 창 제목, 브라우저 도메인, URL, 문서명 같은 실제 상세 수집 구현은 비공개 Pro 모듈 또는 별도 승인된 후속 구현으로 둔다.
- Pro 모듈이 없을 때 Community UI는 관련 기능을 숨기거나 비활성화하거나 사용할 수 없음을 명확히 안내해야 한다.
