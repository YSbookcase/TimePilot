# 앱 분류 추천 설계

영문 에이전트용 문서: `docs/features/APP_CLASSIFICATION_RECOMMENDATION.md`.

## 1. 목표

앱 분류 추천은 기록된 앱이 많아졌을 때 사용자가 모든 앱을 직접 분류해야 하는 부담을 줄이는 기능이다.

첫 단계의 추천 기능은 다음 질문에 답해야 한다.

```text
이 미분류 앱은 어떤 분류일 가능성이 높은가?
```

다만 추천은 자동 결정이 아니며, 사용자가 승인했을 때만 실제 분류로 적용되어야 한다.

---

## 2. 기본 원칙

- 자동 분류는 추천일 뿐이다.
- 사용자가 승인한 경우에만 분류를 적용한다.
- 사용자가 직접 지정한 분류는 자동으로 덮어쓰지 않는다.
- 1차 대상은 미분류 앱이다.
- 이미 분류된 앱은 나중에 추천과 현재 분류가 다를 때 `검토 필요` 상태로 보여줄 수 있다.
- 창 제목, URL, 문서명, 명령줄 인자처럼 개인정보 민감도가 높은 정보는 기본 추천 근거로 사용하지 않는다.

---

## 3. Community 범위

Community 버전에는 로컬 우선의 실용적인 1차 추천 기능을 넣을 수 있다.

- IDE, 브라우저, 메신저, 게임 런처, 미디어 플레이어, 시스템 앱 등 잘 알려진 앱 사전
- 프로세스명, 제품명, 파일 설명 기반의 보수적인 매칭
- `알려진 브라우저 앱`, `알려진 게임 런처` 같은 추천 근거 표시
- 앱 분류 관리 화면에서 추천 분류 표시
- 선택한 미분류 앱에 추천 분류 적용
- 사용자가 직접 바꾼 분류는 사용자 선택으로 보호

이 범위라면 클라우드 조회나 과도한 상세 추적 없이도 분류 부담을 줄일 수 있다.

---

## 4. Pro 또는 후속 후보

다음 항목은 후속 작업 또는 Pro 후보로 분리하는 것이 좋다.

- 인터넷 검색 기반 분류
- 브라우저, 웹사이트, 문서 단위 분류
- 계속 실행되는 규칙 기반 자동 분류
- 여러 PC 간 추천 동기화
- 고급 분류 분석과 장기 추세 분석
- 사용자 지정 분류까지 대량 덮어쓰기
- 전체 변경 이력을 보여주는 고급 감사 화면

이 기능들은 가치가 있지만 복잡도, 개인정보 리스크, 제품 경계 문제가 커진다.

---

## 5. 권장 데이터 모델

현재 앱 분류 모델은 `apps` 테이블에 대표 분류 1개를 저장한다.

추천 기능까지 고려하면 분류 값만으로 사용자의 의도를 추정하지 말고, 출처를 별도로 저장하는 편이 좋다.

후보 컬럼:

```text
apps.primary_category_source
apps.primary_category_updated_at
apps.recommended_category_id
apps.recommended_category_reason
apps.recommended_category_confidence
apps.recommended_category_updated_at
```

분류 출처 후보:

```text
none
user
recommendation
import
system
```

의미:

- `none`: 분류가 지정되지 않음
- `user`: 사용자가 직접 선택함
- `recommendation`: 사용자가 추천을 승인해서 적용함
- `import`: 복원 또는 가져오기에서 들어옴
- `system`: 기본 시스템 동작으로 지정됨

사용자가 직접 분류를 바꾸면 `primary_category_source`는 `user`가 되어야 한다.

추천을 승인해서 적용한 경우에는 `primary_category_source`를 `recommendation`으로 둘 수 있다.

---

## 6. 추천 근거

처음에는 로컬에 있는 보수적인 정보를 사용한다.

- 프로세스명
- 앱 표시 이름
- 사용자 별칭
- 제품명
- 파일 설명
- 회사명
- 알려진 앱 사전
- 알려진 Windows 시스템 프로세스 목록

`Program Files 경로에 있음` 같은 넓은 규칙은 앱의 사용 목적을 잘 설명하지 못하므로 피한다.

---

## 7. UI 방향

앱 분류 관리 화면에 추천 정보를 추가한다.

후보 컬럼:

- 추천 분류
- 추천 근거
- 분류 출처
- 검토 필요

후보 동작:

- 선택한 앱에 추천 적용
- 현재 보이는 미분류 앱에 추천 일괄 적용
- 선택한 앱의 추천 무시
- 추천 있음 필터
- 검토 필요 필터

UI에서는 현재 분류가 어떤 상태인지 구분되어야 한다.

- 미분류
- 사용자가 직접 지정
- 추천을 승인해서 지정
- 가져오기 또는 시스템 지정

---

## 8. 안전 규칙

- 백그라운드에서 추천을 자동 적용하지 않는다.
- `user` 출처의 분류는 사용자가 고급 덮어쓰기 동작을 명시적으로 선택하지 않는 한 덮어쓰지 않는다.
- 일괄 적용 전에는 영향을 받는 앱 개수를 보여준다.
- 가능하다면 직전 분류 변경 1회 되돌리기 흐름을 유지한다.
- 온라인 조회는 사용자가 명시적으로 실행하기 전에는 사용하지 않는다.

---

## 9. 구현 순서

1. 분류 출처 컬럼과 마이그레이션을 추가한다.
2. 기존에 수동 관리된 분류를 가능한 범위에서 사용자 지정으로 보호한다.
3. 로컬 알려진 앱 추천 서비스를 추가한다.
4. 앱 분류 관리 화면에 추천 분류와 추천 근거를 표시한다.
5. 선택한 앱에 추천을 적용하는 동작을 추가한다.
6. 현재 보이는 미분류 앱에 추천을 일괄 적용하는 동작을 추가한다.
7. 온라인 조회, 고급 변경 이력, 자동 규칙은 후속으로 미룬다.

---

## 10. 남은 결정 사항

- 추천을 승인한 분류를 사용자 직접 지정과 계속 구분할지 여부
- 무시한 추천을 저장할지 여부
- 사용자 정의 분류도 추천 대상이 될 수 있는지 여부
- 추천 신뢰도를 사용자에게 보여줄지 내부 판단에만 쓸지 여부
- 추천 일괄 적용 전에 분류 변경 이력이 필요한지 여부
