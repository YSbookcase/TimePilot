# 분류 가져오기 수동 확인

현재 기능 브랜치를 솔루션에서 빌드한 앱으로 확인한다. Store 배포본에 아직 제공되지
않을 수 있다. 실제 사용 기록을 삭제하거나 전체 복원을 실행할 필요는 없다.

## 변경 없는 파일

자신의 분류를 내보내 그대로 다시 읽었을 때 변경이 0개라면 정상이다. 적용 버튼과 백업
선택이 비활성화되고, 적용할 변경이 없다는 상태 안내가 나온다. 이때는 닫으면 된다.

## 변경 있는 파일

샘플: `fixtures/category-import-smoke.json`

이 파일에는 **가져오기 확인용 (테스트)**라는 사용자 분류 하나만 있으며 앱 지정은 없다.
이 파일을 읽는 것만으로는 데이터가 바뀌지 않는다. 적용하면 현재 DB에 이 분류 하나를
추가하므로, 기존에 같은 이름이 없는지 미리보기에서 확인한다. 기존 앱 분류·사용 기록·
설정·시간을 변경하는 샘플이 아니다.

1. `파일 > 앱 분류만 가져오기`에서 샘플 JSON을 선택한다.
2. 추가할 분류 1개, 지정할 앱 0개인지 확인한다. 취소/닫기를 먼저 확인해도 된다.
3. `적용 전 안전 백업 만들기 (권장)`는 기본 체크다. 그대로 두면 백업 후 적용한다.
4. 백업 없이 확인하려면 체크를 해제한다. `백업 없이 적용`의 확인창에서 취소하면
   아무 작업도 하지 않으며, 동의해야 백업 없이 적용한다.
5. 진행 표시와 완료 문구를 확인한다. 백업을 선택한 경우 경로를, 생략한 경우
   백업을 생성하지 않았다는 안내를 표시한다.
6. 같은 샘플을 다시 읽으면 변경 0개여야 한다.
7. 확인을 끝내면 앱 분류 관리에서 테스트 분류가 어떤 앱에도 지정되지 않았는지
   확인한 뒤 삭제한다. 삭제 후에는 같은 샘플로 다시 테스트할 수 있다.

백업 생략 선택은 이 창에서만 유효하며 다음에 열면 다시 기본 체크된다. 실제 분류를
옮길 때에는 복구할 수 있도록 백업 생성을 권장한다. 백업 파일은 암호화되지 않으며
일반 백업 폴더가 Store 제거/초기화로 삭제될 수 있다는 점에 주의한다.

## 충돌 정책 확인 (폐기 가능한 테스트 데이터)

위 샘플은 새 분류 하나만 추가하므로 기존 지정 교체를 검증하는 파일은 아니다.
교체 확인을 위해 일상 DB의 분류를 일부러 바꿀 필요는 없다. 자동 테스트에서는 합성 DB로
아래 상황을 구성하며, 수동 확인도 별도 테스트 데이터에서 진행한다.

1. 같은 앱을 현재 데이터에서는 `게임`, 파일에서는 다른 분류로 지정한다.
2. 기본 `현재 분류 유지`에서는 유지로 표시되는지 확인한다.
3. `파일 분류 우선`에서는 사용자 지정 교체가 미리보기에 나타나는지 확인한다.
4. 색상 옵션은 기본 해제다. 선택하면 현재/파일 색상과 색상 변경 개수가 나타나야 한다.
   이 변경은 파일에 없는 앱에도 공유 분류를 통해 영향을 줄 수 있다.
5. 적용 확인창을 취소하면 백업/분류 적용이 시작되지 않아야 한다. 동의하면 표시한 계획만
   적용하고, 사용자 지정 교체와 색상 변경이 함께 반영되는지 확인한다.
6. 파일에 없는 앱, 파일에서 미분류인 앱, 실행 경로 충돌 앱은 초기화/교체하지 않아야 한다.
7. 미리보기 이후 현재 데이터를 바꾸면 승인했더라도 적용을 거부해야 한다.

관련 자동 검증: `CategoryImportPolicyTests`,
`CategoryImportFormTests.PolicySelectionRebuildsPreviewAndOnlyAppliesConfirmedVisiblePlan`.
