# Store 제출 전 갭 검토

이 문서는 현재 열린 이슈를 Microsoft Store 제출 준비 관점에서 분류한다.
넓은 연구 이슈를 출시 차단 항목으로 오해하지 않기 위한 기록이다.

## 현재 위치

- Partner Center 개인 개발자 등록은 완료했다.
- Pro 기능과 사업 운영 준비가 되기 전까지 공개 출시는 무료 초기 공개 테스트로 유지한다.
- Microsoft Store 앱 이름을 예약하기 전에 공개 제품명을 확정해야 한다.
- 현재 열린 이슈 대부분은 연구 또는 장기 구조 개선 작업이며, 직접적인 제출 차단 항목은 아니다.

## 이슈 분류

### Store 제출 전 차단 항목

현재 열린 이슈 중 단독으로 Store 제출을 막는 항목은 없다.

다만 제출 전에는 다음 확인을 끝내야 한다.

- 최종 공개 제품명과 Store 제목을 확정한다.
- 개인정보처리방침과 지원 페이지가 최종 제품명 및 URL 슬러그를 사용하도록 맞춘다.
- 현재 앱이 선택형 상세 추적을 기본으로 켜지 않는지 확인한다.
- Store 스크린샷이 아직 없는 Pro, 클라우드 동기화, URL 추적, 상세 추적 기능을 암시하지 않는지 확인한다.
- 설치, 실행, 제거, 트레이, 시작 프로그램, 백업, 복원, 내보내기, 로컬 데이터 삭제 동작을 확인한다.

### 제출 전 문서화 또는 확인이 필요한 항목

- #230 로컬 데이터 암호화 및 앱 잠금 정책
  - 첫 무료 공개 테스트에서 앱 단위 사용 기록만 로컬에 기본 저장한다면 필수 구현은 아니다.
  - 암호화를 구현하지 않았다면 Store 개인정보 문구에서 로컬 데이터가 기본적으로 암호화되지 않는다는 점을 명확히 해야 한다.
  - 선택형 상세 추적을 나중에 추가한다면 넓게 제공하기 전에 암호화/앱 잠금을 다시 검토한다.

- #90 선택형 상세 추적 모드
  - Store 제출 필수 기능은 아니다.
  - 명시적 동의, 개인정보 문구, 삭제 정책, 저장 스키마가 준비되기 전까지는 꺼져 있거나 미구현 상태여야 한다.
  - 현재 Store 등록 문구에는 URL, 창 제목, 브라우저 방문 기록 추적을 활성 기능처럼 쓰지 않는다.

- #224 Pro 기능 분리
  - 첫 무료 공개 테스트에는 필수 작업이 아니다.
  - 유료 Pro, 비공개 Pro 저장소, 라이선스, 기능 제한 작업 전에 다시 검토한다.
  - 현재 Store 등록 문구에는 Pro 기능을 광고하지 않는다.

- #65 WinForms 폴더 구조 정리
  - Store 제출 필수 작업은 아니다.
  - 큰 기능 작업 전에 유용하지만, 출시 전에는 사용자에게 보이는 안정성과 패키징 확인을 우선한다.

## 제출 후 후보 작업

- #230은 상세 추적을 계획할 때 개인정보/보안 마일스톤으로 승격할 수 있다.
- #90은 개인정보 및 삭제 정책이 준비된 뒤 Pro 또는 고급 선택 기능 후보로 둘 수 있다.
- #224는 유료 Pro 출시 전에 다시 검토한다.
- #65는 구체적인 기능 작업의 위험을 줄일 때마다 점진적으로 진행한다.

## 다음 개발 우선순위 제안

첫 Store 제출 전에는 큰 새 기능보다 작은 검증과 다듬기 작업을 우선한다.

- 공개 앱 이름을 확정한다.
- 이름 확정 후 사용자에게 보이는 브랜드를 업데이트한다.
- 현재 요약, 타임라인, 상세, 설정, 트레이, 백업, 복원, 데이터 삭제 흐름을 Store 스크린샷 후보로 검토한다.
- Store 등록 문구와 스크린샷 체크리스트를 준비한다.
- MSIX와 MSI/EXE 중 패키징 경로를 결정한다.
- 새 설치 검증을 수행한다.
