# UI 디자인 가이드 - TimePilot

## 1. UI 목표

TimePilot의 UI는 사용자가 오늘 자신의 시간이 어디에 쓰였는지 빠르게 이해하도록 돕는 것을 목표로 한다.

초기 우선순위는 화려함이 아니라 명확성이다. 풍부한 시각 요소를 추가하기 전에 사용 시간 데이터를 쉽게 비교할 수 있어야 한다.

핵심 UI 질문:

```text
오늘 내 시간은 어디로 사라졌는가?
```

---

## 2. MVP UI 방향

- 실용적인 데스크톱 대시보드 스타일을 사용한다.
- 화면 상단에 현재 추적 상태를 표시한다.
- 사용 현황의 중심 화면은 테이블로 구성한다.
- 주간/월간 분석보다 오늘의 사용 현황을 먼저 보여준다.
- 활성 사용 시간과 자리비움 시간을 시각적으로 분리한다.
- 테이블 데이터가 안정화되기 전까지 차트는 보조 요소로 둔다.

MVP UI는 원시 로그 뷰어처럼 동작하지 않아야 한다. 로그는 개발 검증에는 유용하지만, 사용자 화면은 데이터를 요약하고 비교할 수 있어야 한다.

---

## 3. 권장 MVP 레이아웃

### 3.1 상단 상태 영역

실시간 추적 상태를 보여준다.

권장 항목:

- 현재 활성 앱
- 현재 상태, 예: 활성 또는 자리비움
- 오늘의 총 활성 사용 시간
- 오늘의 총 자리비움 시간
- 마지막 갱신 시간

### 3.2 메인 사용 현황 테이블

테이블을 화면의 중심 영역으로 사용한다.

권장 컬럼:

- 앱 이름
- 활성 사용 시간
- 사용 비율
- 마지막 감지 시간
- 상태 또는 분류

데이터 모델이 안정화되면 사용 시간 기준 정렬을 지원하는 것이 좋다.

### 3.3 요약 영역

테이블이 충분히 유용해진 뒤 작은 요약 영역을 추가한다.

권장 요약:

- 오늘 가장 많이 사용한 앱
- 총 활성 시간
- 총 자리비움 시간
- 가장 최근의 활성 앱

---

## 4. 시각 방향

- 마케팅 페이지 같은 구성보다 읽기 쉬운 데스크톱 UI를 우선한다.
- 명확한 라벨과 일관된 간격을 사용한다.
- 데이터 가독성을 떨어뜨리는 장식적 레이아웃은 피한다.
- 추적 데이터가 신뢰할 수 있게 되기 전까지 패널을 과하게 늘리지 않는다.
- 가장 중요한 숫자인 앱별 활성 사용 시간이 쉽게 눈에 들어와야 한다.

WinForms MVP 작업에서는 사용 기록을 `ListBox`보다 `DataGridView`로 보여주는 것이 좋다. 앱별로 표시해야 할 의미 있는 필드가 여러 개이기 때문이다.

---

## 5. 개인정보 기준

- 창 제목은 기본적으로 저장하거나 표시하지 않는다.
- 기본 표시 식별자는 프로세스 이름 또는 앱 표시 이름을 사용한다.
- 자세한 활동 맥락은 사용자가 명시적으로 선택한 경우에만 다룬다.
- 프로젝트 계획의 로컬 우선 원칙을 유지한다.

---

## 6. 확장 순서

권장 UI 확장 순서:

1. 현재 상태와 앱별 사용 현황 테이블
2. 일별 활성 시간과 자리비움 시간 요약
3. 기본 필터링과 정렬
4. 사용 비율을 보여주는 간단한 차트
5. 주간/월간 분석
6. 제외 앱과 추적 주기 설정

Foreground 사용 추적, 자리비움 추적, 로컬 저장이 안정화되기 전에는 넓은 범위의 대시보드 기능을 먼저 추가하지 않는다.
