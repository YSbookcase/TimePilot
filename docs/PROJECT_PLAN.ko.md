# 프로젝트 기획서 - TimePilot

## 1. 프로젝트 개요

**프로젝트명:** TimePilot

**목표:**
사용자의 PC 사용 패턴을 자동으로 기록하고 분석하여, 시간 관리 및 자기개발에 도움을 주는 데스크탑 애플리케이션 개발

**핵심 컨셉:**
"내 시간이 어디로 사라지는지 정확히 보여주는 도구"

---

## 2. 개발 목적

- 사용자가 자신의 시간 사용을 객관적으로 인식할 수 있도록 함
- 특정 프로그램(게임, 유튜브, IDE 등) 사용 시간을 자동 기록
- 장기적으로 생산성 향상 및 자기관리 도구로 확장

---

## 3. 주요 기능

### 3.1 프로세스 추적 기능 (Core)

- 실행 중인 프로그램 자동 감지
- 활성 창 기준 사용 시간 측정
- 활성 창 사용 시간, 유휴 시간, 백그라운드 프로세스 실행 시간을 분리해서 추적
- 초기에는 시간 추적에 집중하고, CPU/메모리/디스크/네트워크 같은 리소스 추적은 향후 확장으로 보류
- 일정 주기(예: 1초~5초)로 상태 체크
- 1초 foreground 감지 루프는 가볍게 유지
- 무거운 DB 조회와 백그라운드 프로세스 집계는 가능한 한 UI 스레드 밖에서 처리
- 위험한 백그라운드 프로세스 추적 설정은 안전모드로 보호

**저장 데이터**

- 프로그램 이름 및 표시 이름
- 시작 시간
- 종료 시간
- 총 사용 시간
- 추적 유형 (활성 창, 유휴, 프로세스 실행 등)
- 실행 세션 상태와 종료 사유
- 앱 중단과 시스템 재시작을 구분하기 위한 Windows 시스템 시작 시각 추정값

---

### 3.2 시간 집계 기능

- 일별 사용 시간
- 주간 / 월간 통계
- 프로그램별 총 사용 시간
- 하루 데이터가 얼마나 완전한지 이해할 수 있도록 기록 커버리지와 미기록 시간 통계를 추가할 예정

---

### 3.3 시각화 (UI)

- 프로그램별 사용 비율 (차트)
- 시간대별 사용 패턴
- 가장 많이 사용한 앱 TOP 리스트

---

### 3.4 사용자 설정

- 추적 제외 프로그램 설정 (예: 시스템 프로세스)
- 기록 주기 설정
- 자동 시작 여부
- 트레이 상주 모드
- Windows 시작 시 자동 실행 설정
- 성능 진단 표시 설정
- 데이터 폴더 열기 및 로컬 사용 기록 삭제

---

## 4. 시스템 구조

### 4.1 전체 구조

- Solution
  - `TimePilot.Core` - 비즈니스 로직
  - `TimePilot.Infrastructure` - 데이터 저장
  - `TimePilot.UI` - UI
  - `TimePilot.App` - 실행 진입점

---

### 4.2 주요 모듈

#### 1. Process Tracker

- 현재 활성 프로그램 감지
- 활성 창 변경 감지
- 백그라운드 프로그램의 실행/종료를 시간 기준으로 감지
- CPU/메모리 같은 리소스 지표는 초기 추적 범위에서 제외

#### 2. Session Manager

- 활성 창 세션, 유휴 세션, 프로세스 실행 세션 관리
- 시작/종료 기록

#### 3. Data Storage

- 로컬 DB (SQLite 예정)
- 로그 저장 및 조회

#### 4. Analytics Engine

- 시간 집계
- 통계 계산
- 미기록 또는 미추적 구간을 원인을 단정하지 않고 설명

---

### 4.3 현재 MVP 구현 메모

현재 구현은 모든 추적과 UI를 하나의 WinForms 데스크톱 프로세스 안에서 처리하는 MVP 구조다. 초기 제품 단계에서는 단순성과 빠른 검증을 위해 이 구조를 유지한다.

현재 구현된 기능은 다음과 같다.

- 활성 창 사용 시간 추적
- 유휴 세션 추적
- 백그라운드 프로세스 실행 세션 추적
- 앱 메타데이터와 아이콘 표시
- 요약, 타임라인, 상세 탭
- 선택 앱 실행 구간 목록
- 사용 데이터 CSV 내보내기
- 트레이 상주 모드
- Windows 시작 시 자동 실행 설정과 첫 실행 안내
- 중복 실행 방지
- Windows 설치 파일과 무설치 패키지 빌드 스크립트
- 타임라인의 TimePilot 미실행 구간 표시
- 위험한 백그라운드 추적 설정 안전모드
- 성능 진단 표시 설정

현재 설계 원칙은 다음과 같다.

- 사용 기록은 SQLite에 로컬 저장한다.
- 시간 값은 UTC로 저장하고 UI에서는 로컬 시간으로 표시한다.
- 창 제목, 명령줄 인자, 문서명, 웹페이지 제목은 기본 저장하지 않는다.
- 리소스 지표는 시간 모델이 안정화된 뒤로 미룬다.
- 큰 재작성보다 기존 WinForms 구조를 점진적으로 개선한다.
- 기본 앱 분류와 로컬 추천은 자동 백그라운드 결정이 아니라 사용자가 승인해서 적용하는 보조 기능으로 다룬다. 자세한 내용은 `docs/features/APP_CLASSIFICATION_RECOMMENDATION.ko.md`를 참고한다.

## 9. 기대 효과

- 자기관리 능력 향상
- 시간 낭비 패턴 개선
- 개발 포트폴리오 활용 가능

---

## 10. 리스크 및 고려사항

- 백그라운드 성능 영향 최소화 필요
- 개인정보 관련 민감도 고려 (로컬 저장 유지)
- 정확한 활성 창 감지 로직 중요
- 초기 단계에서는 대용량 리소스 로그 저장을 피하고 시간 중심으로 기록
- Windows 종료, 다시 시작, PC 전원 버튼 재시작을 앱 비정상 종료로 오해하지 않도록 처리
- 추적 주기와 UI 갱신 주기가 사용자에게 혼동되지 않도록 표시 기준을 명확히 유지

---

## 결론

TimePilot은 단순한 기록 앱이 아니라 사용자의 행동을 바꾸는 도구로 발전 가능성이 있는 프로젝트다.

MVP 기준으로 빠르게 완성 후 UI와 분석 기능을 점진적으로 확장하는 전략이 적합하다.
