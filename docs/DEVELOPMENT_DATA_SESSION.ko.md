# 일상 기록을 이어가는 로컬 개발 실행

개발 PC가 일상 기록 PC일 때 MSIX를 매번 만들지 않고 기존 데이터에 기록을 이어가는 방법이다.
조회 전용이 아니므로 실제 기록과 설정이 변경된다.

## 한 번 설정하기

Store 앱의 환경설정 > 설치 및 데이터 정보에서 사용 중인 데이터 폴더를 확인한다.
프로젝트 루트에서 그 폴더를 명시해 실행한다.

```powershell
.\scripts\configure-development-data.ps1 -DataDirectory "$env:LOCALAPPDATA\Packages\YSBookcase.ActiveLogbook_qx0xt5p8pr0jp\LocalState\TimePilot"
```

로컬 전용 `TimePilot.WinForms/Properties/launchSettings.json`에 `SharedStoreData` 실행 프로필을 만든다.
이 파일은 Git에서 제외되며 다른 기존 프로필은 보존한다. 이 설정 명령 자체는 DB 내용을 읽거나 변경하지 않는다.

## 반복 개발하기

1. 처음에는 Store 또는 이전 빌드 앱을 완전히 종료한다. 트레이에 숨기는 것과 종료는 다르다.
2. Visual Studio에서 WinForms 프로젝트를 시작 프로젝트로 하고 실행 프로필을 `SharedStoreData`로 선택한다.
3. F5로 실행해 테스트하고, 이후에도 그 앱을 켜두면 같은 DB에 계속 기록한다.
4. 다음 빌드 전에는 앱을 종료하거나 디버깅을 중지하고 다시 F5를 누른다. 매번 Store 앱으로 돌아갈 필요는 없다.

터미널에서도 같은 프로필을 사용할 수 있다.

```powershell
dotnet run --project TimePilot.WinForms --launch-profile SharedStoreData
```

프로필이 보이지 않으면 프로젝트를 다시 열어 확인한다. 실행 후 제목의 `[DEV]`와 설치 및 데이터 정보의
실제 DB 경로를 확인한다. 기록이 쌓이고 종료·재실행 뒤에도 같은 기록이 보이는지 확인하면 된다.

## 보호 장치와 주의점

- 기존 단일 실행 제한은 유지한다. 개발 앱이 기존 앱을 강제로 종료하거나 두 앱이 함께 기록하게 하지 않는다.
- 매 실행 전 `%LOCALAPPDATA%\ActiveLogbookDevelopment\backups`에 검증된 안전 ZIP을 만든다.
  단순 파일 복사가 아니라 SQLite 스냅샷 백업을 사용한다. DB가 크면 창이 뜨기까지 시간이 걸릴 수 있다.
- 이 ZIP에는 개인 데이터가 들어 있다. 업로드하지 않으며 자동 보관 정리로 삭제하지도 않는다.
  자주 실행하면 용량이 늘어나므로 필요할 때 직접 정리한다.
- 데이터/설정 파일이 없거나 잘못됐거나 백업이 실패하면 실행을 중단한다. 빈 DB 생성이나 이전 EXE 폴더로의 자동 대체는 하지 않는다.
- 데이터 위치 자동 이전은 건너뛴다. 기존 EXE 폴더에 따로 쌓인 테스트 기록을 Store 기록에 자동 병합하지 않는다.
- 사용 기록·분류·설정·정렬·창 배치는 실제 데이터다. 삭제/복원/설정 초기화도 실제 작업이므로 주의한다.
- 개발 실행에서 Windows 자동실행 등록·동기화와 첫 자동실행 질문은 생략하고 해당 설정은 잠근다.
  Store의 시작 앱 등록은 유지한다. 재부팅 후 Store 앱이 켜졌다면 개발 실행 전에 종료한다.
- Store로 돌아가려면 개발 앱을 종료하고 설치된 Store 앱을 연다. 데이터 폴더를 옮기지 않았으므로 이어진 기록을 사용한다.
  단, 오래된 Store 버전이 설정을 다시 저장하면 새 개발 설정 항목을 보존하지 못할 수 있다. 새 기능의 설정 호환성은 별도로 확인한다.
- DB 스키마나 호환되지 않는 설정 형식을 바꾸는 작업은 이 모드가 아니라 폐기 가능한 복사본으로 검증한다.
  일반 저장소 초기화는 계속 실행되므로 안전 백업만으로 모든 개발 코드의 위험이 없어지는 것은 아니다.

실행 프로필 없이 EXE를 직접 열면 기존 EXE 저장 위치 선택이 유지된다.
경로 지정은 비패키지 앱의 `--data-dir "절대 경로"` 옵션으로만 켜진다.
샘플 데이터 생성·삭제 등 관리 인자와 함께 쓰거나 MSIX 안에서 사용하면 거부한다.
Store 설치·업데이트·자동실행 최종 검증에는 여전히 MSIX가 필요하다.

Pro 연동은 별도 계약이며, 이 프로필이 Pro 데이터 API가 되는 것은 아니다.

## 종료·재실행 확인 기준

확인 대상은 설치된 Store 앱이 아니라 `SharedStoreData` 프로필로 실행한 로컬 개발 앱이다.
트레이 메뉴의 종료로 완전히 닫은 다음 같은 프로필로 다시 실행한다.
두 번 모두 제목의 `[DEV]`, 설치 및 데이터 정보의 같은 DB 경로, 이전 기록이 유지되는지 확인한다.
EXE를 인자 없이 직접 열면 다른 데이터 위치를 사용할 수 있으므로 이 확인을 대신하지 못한다.

자동실행 체크박스와 시작 표시 방식이 회색인 것은 이 프로필의 의도된 제한이다.
실제 Windows 자동실행 변경과 로그인·재부팅 검증은 설치된 MSIX 앱에서 별도로 수행한다.
