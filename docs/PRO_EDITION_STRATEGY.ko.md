# TimePilot Community / Pro 전략

## 1. 목적

이 문서는 TimePilot을 공개 MIT 라이선스 기반의 Community 버전과 향후 유료 Pro 버전으로 나눌 가능성을 검토하기 위한 기준 문서다.

핵심 목적은 다음과 같다.

- 이미 공개된 기능과 향후 비공개로 개발할 수 있는 기능의 경계를 명확히 한다.
- 공개 저장소에 Pro 전용 코드를 실수로 포함하지 않도록 한다.
- WinForms MVP 구조에서 Pro 기능을 붙일 수 있는 구조 개선 방향을 정리한다.
- 기존 GitHub Issue 중 Community 기능, Pro 후보, 구조 개선 과제를 구분한다.
- Community 버전이 혼자서도 충분히 쓸 만한 기본 제품이 되도록 기준을 세운다.

## 2. 현재 라이선스 전제

현재 공개 저장소의 TimePilot 코드는 MIT License로 제공된다.

MIT License로 공개된 코드는 사용, 복사, 수정, 배포, 상업적 사용이 넓게 허용된다. 따라서 이미 공개 저장소에 올라간 기능과 코드는 나중에 Pro 전용 기능으로 되돌리기 어렵다.

운영 원칙은 다음과 같다.

- 이미 공개된 기능은 Community 기능으로 인정한다.
- Pro로 판매할 가능성이 있는 구현 코드는 공개 저장소에 커밋하지 않는다.
- 공개 저장소에는 Pro 기능을 붙일 수 있는 인터페이스, 확장 지점, 문서, 이슈까지만 둘 수 있다.
- Pro 전용 구현, 라이선스 확인, 고급 분석 코드는 별도 비공개 저장소에서 관리한다.

## 3. 에디션 구분 원칙

### Community에 남기는 기준

Community 버전은 TimePilot의 핵심 가치인 "내 시간이 어디로 사라지는지 확인한다"를 혼자서도 충분히 사용할 수 있어야 한다.

Community에 포함하는 것이 자연스러운 기능은 다음과 같다.

- 자동 앱 사용 기록
- 일 단위 요약
- 특정 날짜 요약
- 일 단위 타임라인
- 상세 실행 기록의 기본 조회
- 선택 앱 실행 구간 목록
- 유휴 시간 감지
- 기록 커버리지와 미기록 구간 안내
- 로컬 SQLite 저장
- 기본 CSV 내보내기
- 트레이 상주
- Windows 시작 시 자동 실행 설정
- 기본 환경 설정
- 데이터 삭제와 저장 위치 확인
- 기본 한국어/영어 UI
- 실행 진단, 안전모드 안내처럼 신뢰성에 필요한 기본 진단 기능
- 이미 공개 저장소에 구현된 기능

### Community 완성 기준

이번 일반판 개발 사이클에서 Community는 다음 수준을 목표로 한다.

- 사용자가 설치 후 별도 설명 없이 오늘의 사용 앱, 사용 시간, 타임라인을 확인할 수 있다.
- 날짜를 바꿔 과거 하루 기록을 요약, 상세, 타임라인에서 확인할 수 있다.
- 백그라운드 앱 추적이 꺼져 있거나 안전모드로 비활성화되었을 때 사용자가 상태를 바로 이해할 수 있다.
- 기록이 없는 날, TimePilot이 실행되지 않은 구간, Windows 종료/재시작에 따른 종료 사유가 불필요한 오류처럼 보이지 않는다.
- 기본 데이터 내보내기로 사용자가 자기 데이터를 다른 도구에서 확인할 수 있다.
- 최소한의 앱 표시 이름 또는 분류 기능을 통해 사용자가 모르는 앱을 이해할 수 있는 길을 제공한다.
- Community 기능은 로컬 우선과 개인정보 보호 원칙을 유지한다.

### Community에서 아직 부족한 기능

현재 구현 기준으로 Community 완성도를 높이기 위해 남은 주요 후보는 다음과 같다.

- 요약 탭 특정 날짜 선택 UI 개선
- 기본 원본 데이터 내보내기
- 앱 표시 이름 또는 최소 분류 기능
- 시각적으로 이해하기 쉬운 타임라인
- 기록 커버리지 표시 위치와 해석 기준 정리
- 유휴 기준 저장과 유휴 통계 해석 개선
- 화면 정렬 상태 저장과 초기화

### Pro 후보 기준

Pro는 단순 기록 자체를 막는 것이 아니라, 기록을 더 깊게 분석하고 장기간 관리하는 기능에 집중한다.

Pro 후보로 적합한 기능은 다음과 같다.

- 주간, 월간, 연간 고급 통계 대시보드
- 장기 추세 비교
- 시간대별 사용 패턴 시각화
- 고급 활동 타임라인 시각화
- 목표 시간 설정과 초과 알림
- 집중도, 분산도, 앱 전환 패턴 분석
- 고급 리포트 생성
- Excel 또는 PDF 리포트 내보내기
- 데이터 백업, 복원, 암호화
- 여러 PC 데이터 병합
- 규칙 기반 별칭, 아이콘, 카테고리 고급 관리
- 선택형 상세 추적 모드
- 브라우저, 웹사이트, 문서 단위 추적처럼 개인정보 민감도가 높은 고급 추적
- 자동 인사이트 또는 요약 코멘트

### 반복 기간과 시간대 통계 후보

요약 기간 개선 논의에서 나온 반복 요일 필터와 시간대별 사용 분포는 Community 기본 조회와 Pro 고급 분석의 경계를 나누어 검토한다.

Community에 둘 수 있는 범위는 사용자가 이미 가진 기록을 기본적인 기간 조건으로 확인하는 기능이다.

- 선택한 기간 안에서 전체 요일, 월~금, 월~토, 토~일, 일요일 제외 같은 단순 요일 필터로 요약을 다시 계산한다.
- 특정 시작일과 종료일을 달력에서 선택해 사용자 지정 기간을 조회한다.
- 선택한 기간 안에서 시작 시간과 종료 시간을 지정해 특정 시간대만 집계한다. 예를 들어 `09:00~18:00`, `20:00~02:00`처럼 업무 시간이나 야간 사용 시간을 확인한다.
- 선택한 기간의 기본 앱 사용 시간, 활성 사용 시간, 앱 전환 횟수 같은 기존 요약 지표를 같은 화면에서 보여준다.

Pro 후보로 분리하기 좋은 범위는 사용 패턴을 장기적으로 해석하거나, 확률 분포처럼 사용 리듬을 분석하는 기능이다.

- 시간대별 활성 사용 시간 분포를 24시간 히트맵이나 막대 그래프로 보여준다.
- 새벽, 아침, 오후, 저녁, 밤처럼 시간대 버킷별 사용 비중을 계산한다.
- 특정 시간대에 많이 사용하는 앱, 앱 분류, 활동 유형을 Top N 형태로 보여준다.
- 평일 밤, 월~토 오전, 주말 새벽처럼 요일 필터와 시간대 필터를 결합해 패턴을 비교한다.
- 자정을 넘는 시간 범위, 반복 요일, 사용자 지정 기간을 조합해 사용 리듬을 해석한다.
- 앱별로 어느 시간대에 사용이 몰리는지 비율로 보여준다.
- 장기 데이터에서 사용 리듬 변화, 집중 시간대, 분산도, 야간 사용 증가 같은 자동 인사이트를 만든다.

이 기능군은 `내가 컴퓨터로 무엇을 했는가`를 넘어 `언제 어떤 활동을 반복하는가`를 설명한다. 따라서 첫 무료 Store 공개 테스트에는 필수로 넣지 않는다. 기본 날짜 범위, 요일 필터, 단순 시간 범위 필터는 Community 후보로 남기되, 시간대 분포 시각화와 리듬 분석은 Pro 후보로 유지한다.

## 4. 기존 Issue 분류

현재 열린 Issue는 다음 기준으로 다시 검토할 수 있다.

### Community 개선으로 보는 것이 자연스러운 Issue

- `#95` 날짜 선택 UI의 중복 달력 버튼 정리
- `#105` 최근 실행 종료 사유와 비정상 종료 이력 표시
- `#106` 도움말 메뉴에 후원 링크 추가
- `#108` 유휴 세션에 당시 유휴 기준 저장
- `#113` 상세 탭에 백그라운드 앱 추적 비활성 안내 추가
- `#85` 기록 커버리지 표시 위치 및 기준 재검토
- `#71` 화면 정렬 상태 저장 및 초기화 추가
- `#70` 원본 데이터 내보내기 추가

이들은 기본 사용성, 이해 가능성, 데이터 소유권, UI 안정성에 해당하므로 Community 범위에 두는 것이 자연스럽다.

### Community와 Pro 범위를 나눌 수 있는 Issue

- `#22` 앱 표시 이름 사용자 지정 기능 추가
- `#55` 사용자 지정 기간 요약 추가
- `#56` 시각적 활동 타임라인 추가
- `#57` 시간대별 사용 패턴 시각화 추가
- `#60` 사용 기록 백업 및 복원 추가
- `#87` 앱 정보 검색 및 사용자 분류 기능 검토
- `#140` 앱 자동 분류 추천 방식 검토
- `#90` 선택형 상세 추적 모드 검토
- `#107` 타임라인 긴 사용 구간 강조 표시 추가

예를 들어 앱 표시 이름 사용자 지정은 기본 별칭 변경은 Community로 둘 수 있고, 규칙 기반 자동 분류, 아이콘 관리, 카테고리 분석은 Pro 후보로 둘 수 있다.

앱 자동 분류 추천은 로컬 알려진 앱 사전과 사용자 승인 적용은 Community에 둘 수 있고, 인터넷 조회, 지속 실행되는 규칙 기반 자동화, 고급 분류 분석은 Pro 후보로 나눌 수 있다. 자세한 기준은 `docs/features/APP_CLASSIFICATION_RECOMMENDATION.ko.md`를 참고한다.

사용자 지정 기간 요약도 특정 날짜, 이번 주, 지난주, 이번 달, 지난달, 올해, 작년, 단순 요일 필터, 단순 시간 범위 필터 같은 기본 조회는 Community에 둘 수 있고, 장기 추세 비교, 시간대별 사용 분포, 요일과 시간대를 결합한 리듬 분석, 고급 분석 대시보드는 Pro 후보로 나눌 수 있다.

시각적 타임라인은 하루 사용 흐름을 이해하는 기본 막대형 보기는 Community로 둘 수 있고, 장기 비교, 태그별 레이어, 집중도 분석, 자동 해석은 Pro 후보로 나눌 수 있다.

### 구조 개선 선행 Issue

- `#65` WinForms 코드 폴더 구조 정리
- `#36` 추적 엔진과 UI 분리 구조 검토

`Form1`의 1차 책임 분리는 완료되었다. 현재 `Form1.cs`에는 상태와 상위 조립 순서만 남고, 화면·추적·데이터 관리·설정 책임은 기능별 partial과 보조 클래스로 이동했다. 현재 구조는 `docs/architecture/WINFORMS_STRUCTURE.ko.md`를 참고한다.

다만 partial 분리는 독립 모듈이나 플러그인 계약이 아니다. 다음 구조 과제는 추적 엔진과 UI의 실제 경계, 읽기 전용 분석 계약, 메뉴와 분석 창 등록 지점을 정의하는 것이다.

## 5. Pro 코드 관리 방식

### 권장 방식

초기에는 다음 방식을 권장한다.

```text
공개 저장소
- TimePilot Community
- MIT License
- 기본 UI, 기본 추적, 기본 분석, 기본 내보내기
- Pro 기능을 붙일 수 있는 확장 지점

비공개 저장소
- TimePilot Pro
- Pro 전용 기능 구현
- 라이선스 확인
- 고급 분석, 리포트, 자동화 기능
```

### 비공개 저장소 시작 방식

처음부터 복잡한 플러그인 구조를 만들 필요는 없다.

Pro 기능이 실제로 1~2개 이상 구체화되면 비공개 저장소를 만들고, 공개 저장소를 기반으로 시작할 수 있다. 다만 공개 저장소와 비공개 저장소가 오래 갈라지면 병합 비용이 커지므로, 가능한 한 공통 코드는 공개 저장소에서 유지하고 Pro 전용 코드는 별도 모듈로 분리하는 방향을 목표로 한다.

## 6. Add-on 구조를 위한 리팩터링 방향

1차 리팩터링으로 `Form1.cs` 중심의 책임 집중은 해소했다. 이제 partial 파일에 Pro 조건문을 추가하는 대신 공개 계약을 통해 선택 기능을 등록할 수 있는 구조를 설계한다.

Pro 기능을 장기적으로 붙이려면 다음 확장 지점이 필요하다.

- 탭 등록 지점
- 메뉴 항목 등록 지점
- 설정 화면 섹션 등록 지점
- 분석 카드 또는 요약 패널 등록 지점
- CSV/리포트 내보내기 등록 지점
- 기능 사용 가능 여부를 판단하는 인터페이스
- Pro 기능이 없을 때도 Community 버전이 자연스럽게 동작하는 fallback

첫 Add-on 구조 검증 사례는 연간 달력 히트맵 기반 사용 통계로 한다. 기존 기록을 읽는 분석 기능이므로 추적 안정성과 개인정보 수집 범위를 바꾸지 않으면서 읽기 전용 데이터 공급자, 메뉴 등록, 별도 분석 창, 언어 전달, fallback 계약을 검증할 수 있다.

공개 저장소에는 우선 `KYS24/Analytics`의 읽기 전용 일별 분석 공급자까지만 둔다. 이 공급자는 날짜별 활성 사용 시간, 유휴 기록 시간, 대표 앱, 기록 상태 지표를 반환하며, Pro 전용 화면이나 라이선스 확인 코드는 포함하지 않는다.

첫 Pro 참조 기능의 공개 가능한 방향은 **주요 사용 분류 중심의 연간 달력**이다. 날짜 셀은 하루의 대표 분류를 가장 먼저 전달하고, 활성 사용 시간은 색상 진하기나 보조 지표로 다룬다. 주요 앱, 유휴 기록 시간, 기록 상태 같은 자세한 정보는 셀 안에 모두 넣지 않고 hover 또는 선택 패널에서 보여주는 방향을 우선 검토한다.

선택형 상세 추적은 이후 Pro 후보로 유지한다. 공개 저장소에서는 정책, UI 계약, 저장 경계, 확장 훅까지만 준비하고, Pro 전용 상세 수집 구현 코드는 공개 Community 구현에 포함하지 않는다.

예상 인터페이스 예시는 다음과 같다.

```csharp
internal interface ITimePilotFeatureModule
{
    string Id { get; }

    void Register(TimePilotFeatureRegistry registry);
}
```

이 구조는 지금 당장 구현을 확정한 설계가 아니라, `Form1`에 기능별 조건문이 계속 쌓이는 것을 줄이기 위한 장기 방향이다.

## 7. 단계별 진행안

### 1단계: 문서와 Issue 정리

- Community / Pro 경계 문서화
- Pro 후보 Issue에 Community 범위와 Pro 후보 범위를 구분
- 구조 개선 Issue에 Add-on 가능성을 고려해야 한다는 내용을 추가

### 2단계: Community 완성도 보강

- 기본 날짜 선택 경험 정리
- 원본 데이터 내보내기
- 기록 커버리지와 미기록 구간 안내 정리
- 앱 표시 이름 또는 최소 분류 기능 검토
- 하루 타임라인의 기본 시각화 개선

### 3단계: WinForms 내부 책임 분리 - 완료

- `Form1.cs`는 상태와 상위 조립 순서만 유지
- 트레이, 날짜, 화면, 추적, 데이터 관리, 설정 책임을 기능별 partial로 분리
- 기존 동작과 Community 기능 범위 유지

### 4단계: UI 등록 지점 만들기

- 탭, 메뉴, 설정 섹션을 등록하는 내부 구조를 만든다.
- 처음에는 공개 저장소 안에서 Community 기능만 등록한다.
- Pro 모듈을 바로 만들지 않더라도 나중에 붙일 수 있는 형태를 준비한다.

### 5단계: Pro 후보 기능 구체화

- 첫 참조 기능: 연간 달력 히트맵 기반 사용 통계
- 주간, 월간, 연간 통계
- 고급 타임라인 시각화
- 앱 분류와 리포트 기능
- 선택형 상세 추적

이 단계부터는 공개 저장소에서 구현할 범위와 비공개 저장소에서 구현할 범위를 먼저 결정한다.

## 8. 주의 사항

- 기존 공개 기능을 나중에 잠그는 방식은 피한다.
- Pro는 기본 기능을 빼앗는 방식이 아니라 고급 분석과 관리 기능을 추가하는 방식이어야 한다.
- 개인정보 민감도가 높은 기능은 기본값을 보수적으로 둔다.
- Pro 기능 때문에 Community 버전의 구조가 불필요하게 복잡해지지 않도록 한다.
- 유료화, 라이선스, 결제, 환불, 세금 문제는 구현 전에 별도 검토가 필요하다.

## 9. 결론

TimePilot은 기본 기록과 일 단위 확인 기능을 Community 버전으로 충분히 제공하고, Pro는 장기 데이터 분석, 고급 시각화, 자동화, 리포트, 데이터 관리 기능으로 확장하는 방향이 자연스럽다.

다만 Pro 기능을 안정적으로 붙이려면 먼저 `Form1.cs` 중심 구조를 점진적으로 분리해야 한다. 따라서 당장의 우선순위는 Pro 기능 구현이 아니라 Community / Pro 경계 문서화, Community 완성도 보강, Add-on 가능성을 고려한 리팩터링이다.
